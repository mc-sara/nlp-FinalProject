# P3 Workflow（精简版）

## Phase 0 冻结现场
- 记录 v3/v4 版本号与 `env.py`、`validator.py`、`scenarios.py` 的 sha256。
- 快照 5 条 v4 轨迹为只读基线。
- 作用：重放"同版"的唯一凭证。

## Phase 1 复核 + 定口径
- 逐条看 `truth.publish_attempts`、`fault_counter_version`、validator 分支。
- 每条出四项：判对/判错、归因、rule_ref、改法。
- 归因分三类：模型错、规则错、待裁定。
- 同步定 Q1–Q4，写进 `spec_version`（v1 起以下为准）。
  - Q1：上限只算有效发布，被硬规则拒绝的那次不计入。v4 的 `validator.py:139` 仍统计全部 publish，会把三条示范全判 FAILED_MODEL，正式口径按有效发布计。
  - Q2：四个故障族一律先查证再决定；`not_published` 不再允许直接补发——否则模型必须知道故障族这一隐藏状态才能区分，等于泄漏 truth，且 PLAN 2.3「确认没有→重发一次」本身就要求先确认。
  - Q3：沿用 `step_limit=16`，不设独立查询预算；查证次数由 verify 预算 3（D1 实测延迟上界 k=2 的 k+1）体现。
  - Q4：`title_too_long` 属硬规则，非注入故障，不消耗有效提交位；示范保留「改标题重发」，但不计入恢复能力。
- 复核结论（取代 v0 初判）：5 条 p1_label 全部判对。v0 初判里「visible 判错」与「not_published 按 Q2 改判」两条撤回，理由见 `p3_review.json` 的 `ratifications`。
- 不拿 `recovery_success_rate=0.0` 当结论。

## Phase 2 制作 3 条示范
- 选 visible、resubmit_unknown、not_published。
- schema 与采集一致，只改动作序列，observation 原样保留。
- 最小改动，便于 diff；至少一条含"改标题重发"。
- 落 `corrected_demos.jsonl`。

## Phase 3 同版重放（门禁）
- 重放前校验 sha256 与 Phase 0 一致，不一致则结论作废。
- 示范动作代替模型输出，逐 step 调 `env.step`。
- 验收：终态 `SUCCESS_*`、`post_count==expected`、无 `DUPLICATE_POST`、step ≤ 16。
- 结果写进 `p3_review.json` 的 `replay` 字段。
- 未通过不放行。

## Phase 4 交付放行
- `p3_review.json`：5 条裁定、口径、版本 sha256、重放结果、追认项。
- `corrected_demos.jsonl`：3 条示范。
- 放行条件：口径落盘 + 3 条重放全绿。
- 完成后整目录同步到服务器 `review/`，本地留一份。

## 文件规范

只保留 3 个文件，平铺在 `P3/`，不新增。

| 文件 | 读法 | 更新时机 |
|---|---|---|
| `P3.md` | 人读 | 流程变更时 |
| `p3_review.json` | 机器读 | 复核、重放完成后 |
| `corrected_demos.jsonl` | 机器读，逐行追加 | 每条示范定稿时 |

字段约定，新增字段前先改本节：

- `p3_review.json`：`status`(draft/final)、`spec_version`、`env_sha256`、`labeling{}`、`spec`(Q1–Q4)、`records[]`、`ratifications[]`、`replay{}`。
- `labeling{}`：`rule`、`validator_pinned_sha256`（产出 5 条标签的版本）、`validator_used_sha256`（本次打标版本）、`why`、`labels_unchanged_for_5_records`。
- `records[]`：`verdict`(pass/fail)、`label`、`rationale`、`rule_ref`、`action`。
- `replay{}`：`status`(pending/pass/fail)、`log`、`gate`、`results[]`（每条示范的 steps / publish 计数 / post_count / expected / 两个版本下的 label / `gate_passed`）。
- `corrected_demos.jsonl`：`demo_id`、`family`、`_status`(todo/done)、`goal`、`scenario_id`、`task`、`system_prompt`、`scenario`、`actions[]`、`final_answer`、`provenance{}`。`task`/`system_prompt`/`scenario` 与采集轨迹逐字段相同，示范可直接拼成 trajectory 供 few-shot 使用。
- `actions[]`：`tool_name`、`arguments`、`result`、`observation`（result 为工具原始返回，observation 为 env 序列化后的模型可见字符串，逐字节未经改写）。
- `provenance{}`：`new_trajectory_id`、`split`、`origin`、`source_id`、`source_sha256`、`correction`、`corrector`、`replayed_at`、`simulator_sha256`、`environment`、`truth_post_count`、`expected_post_count`、`effective_publish_count`、`all_publish_count`、`steps`。

书写规则：一条记录一行、不嵌套；文本空值写 `""`、时间空值写 `null`；不建子目录、不写脚本、不建 README。
